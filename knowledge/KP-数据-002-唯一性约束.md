# KP-数据-002 唯一性约束

## 识别信号

出现**唯一类约束**，或**按多个维度判定"有无记录 / 是否重复"**。

线索词：唯一、不重复、不可重复、已存在、同一个…只能、按 X 唯一、绑定

| 类型 | 需求中的说法 | 例 |
|---|---|---|
| **单值唯一** | "XX 不可重复"、"XX 唯一" | 手机号唯一、编码唯一 |
| **组合维度唯一** | "按 A + B 唯一有效"、"同一设备同一账号当日…" | 账号+浏览器当日记录唯一 |

> ⚠️ **组合维度唯一最容易漏**：需求常写成一句判定（"按当前浏览器+当前账号+当日判定有无记录"），
> 看上去像流程规则，实际是一个**多维唯一性**——必须拆成真值表逐行覆盖。

## 典型测试点

1. 唯一约束成立时：写入 / 判定成功
2. 违反唯一约束时：被拒绝并提示 {文案}（提示是否指明冲突对象）
3. **组合维度真值表**：{维度A} × {维度B} 全组合逐一覆盖（如账号 × 设备 4 组合）
4. 任一维度更换即视为新记录 / 需重新判定
5. 边界：大小写、首尾空格、全半角是否影响唯一判定
6. 唯一范围：全局 / 按公司 / 按项目 / 按用户隔离
7. 并发下唯一性是否被击穿（同时提交两条相同值）

## 典型澄清问题

1. 唯一性按**哪些字段**判定？是否区分大小写与空格？
2. 唯一范围是全局，还是按公司 / 项目 / 用户隔离？
3. 违反唯一性时的提示文案是什么？是否指明与哪条冲突？
4. 历史数据中已存在的重复值如何处理？
