# KP-系统异常-001 外部依赖失败

## 识别信号

需求描述了**对外部系统 / 服务的调用**（短信通道、第三方接口、ERP、AD 域、文件存储、支付…）。

线索词：调用、接口、同步、推送、发送成功、发送失败、第三方、通道

**判定要点**：只要需求提到调用了外部服务，就要问一句"**调用失败时怎么办**"。
需求里常以"**按调用发送成功计算**"这类措辞**暗示**失败是可能的——这就是命中信号。

> 不含"前置配置缺失"（如账号未绑定手机）：那类属于条件校验，留在基线 6 维度处理，不并入本 KP。

## 典型测试点

1. 调用失败时的用户可见表现（提示 / 阻断 / 降级），无白屏、无死循环
2. 失败是否计入业务计数（"按调用发送成功计算" ⇒ **不计入**）
3. 失败后能否立即重试，还是同样受冷却 / 倒计时限制
4. 外部服务恢复后重试成功
5. 超时（服务无响应）时的表现与耗时上限
6. 失败是否留痕（日志 / 可观测），便于排查

## 典型澄清问题

1. 调用失败时是否需要业务降级？提示文案是什么？
2. 失败的调用是否计入次数 / 配额类统计？
3. 失败后是否允许立即重试？有无冷却要求？
4. 外部服务不可用达一定时长时，是否需要人工介入通道？
