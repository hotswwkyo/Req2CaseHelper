# KP-交互-001 二次确认与取消

## 识别信号

出现**会产生状态变更的操作**，或**可取消 / 关闭的界面**。

线索词：二次确认、确认弹窗、确定 / 取消、是否确认、取消、关闭、放弃、返回、必选校验

**判定要点**：凡是"点击后会产生状态变更"的按钮（删除 / 作废 / 关闭 / 提交 / 指派 / 终止 / 重置），
都要问一句"**要不要二次确认**"——需求往往不写，但漏了就是数据事故。

## 典型测试点

1. 入口存在：{操作} 按钮在 {状态} 下可见 / 可用
2. 点击后弹出确认，文案完整（提示对象与后果）：{文案}
3. **确认**后操作生效、状态正确变更
4. **取消**后**不产生任何变更**（状态与数据均不变）
5. 关闭弹窗（X / ESC / 点击遮罩）等效于取消，不产生变更
6. 必选校验：{必选字段} 未选时点确认 → 提示且不提交
7. 重复触发防护：连点确认按钮不产生多条记录

## 典型澄清问题

1. {操作} 是否需要二次确认？确认文案是什么？
2. 取消后是否保留已填内容？
3. 关闭方式有哪些（X / 取消按钮 / ESC / 点遮罩）？是否都等效为取消？
4. 必选字段未选时的提示文案是什么？
